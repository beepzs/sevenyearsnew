# The First Seven Years — website (v1 prototype)

Multi-page static website for **The First Seven Years**: a knowledge library for parents of children aged 0–7, hosted by Dr. Murray Clarke. It covers topic hubs, parent answers, a video library in three formats (full episodes, 7–12-minute short videos, social clips), expert profiles (including featured expert Dr. Bill Sears), Ask the Doctor, medical disclaimers and a book page.

Plain HTML, CSS and JS. No framework and no npm build step. One Python script (standard library only, Python 3.9+) generates every page from a single content model.

Live review build: https://first-seven-years-review.vercel.app

---

## Quick start

```sh
python3 build.py                                   # regenerate all pages into site/
python3 -m http.server 8477 --directory site       # open http://localhost:8477
```

Use a local server, not `file://`. All links are root-relative (`/topics/…`).

## Project structure

```
build.py                 content model + page templates, generates site/**/index.html
site/
  assets/css/main.css    HAND-WRITTEN: design system (tokens, components, responsive, motion)
  assets/js/main.js      HAND-WRITTEN: nav, search typeahead, age tabs, video facade, forms, reveals
  assets/js/search-index.js   GENERATED by build.py
  assets/img/            logo.jpg, dr-murray-clarke.jpg, channel.jpg, favicon.svg (generated)
  **/index.html          GENERATED: do not edit by hand, edit build.py and rebuild
  sitemap.xml, robots.txt, llms.txt    GENERATED
deploy/                  OPTIONAL: Vercel config with a Basic Auth password gate (middleware.js)
deploy.sh                OPTIONAL: builds a noindex review copy into deploy/public and deploys it
```

**Rule of thumb:** edit `build.py` for content and markup, and edit `site/assets/css` and `site/assets/js` directly for styling and behaviour. Then run `python3 build.py`.

## Content model (top of build.py)

| Data | What it drives |
|---|---|
| `TOPICS` (13) | Topic hubs at `/topics/<slug>/`, homepage topic index, search |
| `EXPERTS` | Profiles at `/experts/<slug>/`, bylines, Person schema |
| `_V` → `EPISODES` | Real channel videos with real durations/dates. `fmt` = episode / video / social. Pages at `/videos/<slug>/`; format pages at `/videos/full-episodes/`, `/videos/short-videos/`, `/videos/social-clips/`. Social clips link out to YouTube Shorts |
| `FORMATS` | Labels, colours and blurbs for the three video formats |
| `WELCOME_VIDEO` | YouTube id of the Murray + Bryce welcome video (homepage hero). `None` shows a “coming soon” card |
| `ANSWERS` (10) | Parent answers at `/answers/<slug>/`: short answer, video, review dates |
| `AGES` | Age/stage data (not shown yet — the client phases age browsing in later) |
| `SITE` | Production domain, used for canonical URLs, schema and the sitemap |

Environment flags:
- `STAGING=1` adds `noindex` to every page and a blocking `robots.txt` (use for review builds).
- `OUT=<dir>` writes to another folder instead of `site/`. Copy `site/assets` there first.

## Design system

- **Colours:** navy `#2B3C56` and mint `#A6D6B0`, sampled from the logo. A warm cream base with peach, butter and lilac accents. All are tokens on `:root` in `main.css`.
- **Type:** Fraunces (display, `SOFT` axis) and Figtree (text), from Google Fonts.
- **Hero:** a CSS-only "seven blocks" character. It drops in with a spring, breathes and blinks, and its pupils follow the pointer. All motion respects `prefers-reduced-motion`.
- **Accessibility:** targets WCAG 2.1 AA. Skip link, visible focus, ARIA tabs, a search combobox, inline form errors, 44px touch targets.

## SEO / AI search

- JSON-LD `@graph` on every page: Organization, WebSite + SearchAction, BreadcrumbList, MedicalWebPage + Article (with `reviewedBy`, `lastReviewed`, `speakable`), VideoObject, PodcastEpisode, ProfilePage/Person, CollectionPage/ItemList, Book.
- A "short answer" block at the top of each answer page.
- `sitemap.xml`, `robots.txt` (AI crawlers allowed in production), `llms.txt`.
- Crawlable numbered pagination. YouTube loads as a privacy-enhanced, click-to-play facade, so there are no iframes or cookies until play.

## Not wired yet (front-end only)

- **Ask the Doctor form:** validates on submit and detects red-flag symptoms, then shows a success state. There's no backend yet. Connect it to the chosen email platform, Shopify form or a serverless endpoint.
- **Newsletter and book waitlist:** these show a message only. Connect them to the email platform (still to be confirmed by the client).
- **Analytics:** the code calls `gtag` events (`video_play`, `ask_doctor_submit`) if GA4 is present. The GA4 tag itself isn't added yet.

## Shopify path

The proposal targets Shopify. Each generated page type maps to an OS 2.0 template:

| Here | Shopify |
|---|---|
| episode page | blog article template, `/blogs/episodes/<slug>` |
| answer page | blog article template, `/blogs/answers/<slug>` |
| topic hub | page template + topic metaobject |
| expert profile | expert metaobject |
| book | product template |

`main.css` and `main.js` port across as theme assets unchanged.

## Deploying

Any static host works. Serve `site/` as the web root.

- **Vercel, public:** from a folder containing the built site plus a `vercel.json` with `{"buildCommand": "", "outputDirectory": "."}`, run `npx vercel deploy --prod`.
- **Vercel, password-protected:** use `deploy/` and `./deploy.sh`. Set the `REVIEW_PASSWORD` (and optionally `REVIEW_USER`) environment variables in Vercel. With no password set, all access is denied.
